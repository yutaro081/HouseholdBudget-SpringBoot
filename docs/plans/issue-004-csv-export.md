## 2. 調べた結果〔2026年11月22日。読むだけで調べた〕

〔確かめた〕はコード・ファイルで確かめたこと、〔推測〕は確かめていないこと。

### 2.1 一覧の確かめと検索は、そのまま使える

- 〔確かめた〕`TransactionController.list` は、季節〔`SeasonPeriod.isUnspecified` → `parse` → 空なら `NotFoundException`〕→ 科目〔`CategoryService.get`。ID と `user_id`〕→ `TransactionFilter` の順に作り、`TransactionService.listView` に渡す。確かめの中身は、この 2 行だけ。
- 〔確かめた〕数字でない・範囲外の `category` は、`GlobalExceptionHandler.handleIdTypeMismatch` で 404。
- 〔確かめた〕`TransactionController` に `GET /transactions/{id}` はない〔issue 025 で詳細画面をなくした〕ので、`/transactions/export` とぶつからない。
- 〔確かめた〕絞り込みの検索 `TransactionRepository.findForListByUserIdAndFilter` は、`where t.userId = :userId` で必ず絞り、条件の値が null なら絞らない。並びは一覧と同じ〔日付の新しい順 → `coalesce(receiptGroup, id)` の新しい順 → `id` の順〕。科目・取引先・支払方法は `@EntityGraph` で一緒に読む。条件が全部 null のとき、絞らない一覧と同じ行・同じ並びになることは、`TransactionRepositoryFilterTest.allNullGivesTheUnfilteredList` で確かめ済み。
- 〔推測〕Thymeleaf のリンクの書き方 `@{/transactions/export(year=${…})}` は、値が null の引数を `?year` の形〔値なし〕で出す見込み。そうなると `year` が空の文字として届き、一覧と同じ決まりで 404 になる。→ **指定のある値だけを付ける**〔設計書 2.3。段階 2 のテストで確かめる。Q004-2〕。

### 2.2 同じレシートの印と、分割の番号

- 〔確かめた〕`receipt_group` には、レシートの最初の行の `id` が入る〔`TransactionService.mark`〕。一覧の並びでは、同じレシートの行は必ず隣に並ぶ。→ 上から出てきた順に 1・2・3 と振れば、同じレシートは同じ番号になる。
- ファイルの中だけの番号にする理由〔決まったこと 2〕：DB の値を外に出さない。取り込み〔013〕で「同じ番号 ＝ 1 枚のレシート」とだけ読めばよく、「印はサーバーだけが作る」〔issue 032 の決まったこと 4〕とぶつからない。

### 2.3 入力の決まりと、CSV に入りうる値

- 〔確かめた〕摘要は `@Size(max = 30)` と `strip()` だけ〔`TransactionForm.Line`〕。科目・取引先・支払方法の名前も、`@NotBlank`・`@Size` と `strip()` だけ。**文字の種類は絞っていない**。DB は utf8mb4 なので、絵文字も保存できる。
- 〔確かめた〕`strip()` が取るのは前後の空白だけ。途中の改行・カンマ・`"`・`=` は、送り方を変えれば保存できる〔画面の入力欄は 1 行〕。先頭のタブ・改行は、今の画面からは保存されない。
- 〔確かめた〕金額は `ck_transactions_amount` で 1〜1,000,000〔`schema.sql`〕。マイナスにならないので、金額には数式の印が要らない。

### 2.4 守り〔ログイン、GET、キャッシュ〕

- 〔確かめた〕`SecurityConfig` は `anyRequest().authenticated()`。未ログインは `/login`、古いセッションなら `/login?expired` へ移る。
- 〔確かめた〕`SecurityConfig` に `headers(...)` の指定はない〔標準の守りのヘッダーのまま〕。今の `CacheControlHeaderTest` が見ているのは、画面の URL だけ。
- 〔推測〕CSV の応答にも、標準の `Cache-Control: no-cache, no-store, max-age=0, must-revalidate` と `X-Content-Type-Options: nosniff` が付く。ただし、自分で `Cache-Control` を付けると、Spring Security は上書きしない〔設計書 7.10 のフォントと同じ動き〕。→ 自分では付けず、テストで守る〔決まったこと 9〕。
- GET でよい：データを変えない〔設計書 2.1、7.6〕。〔確かめた〕セッションの Cookie は `same-site=lax`〔`application.properties`〕。〔推測〕ほかのサイトの中から読み込まれたとき〔画像やスクリプトとして〕は Cookie が付かず、ログインしていない扱いになる。

### 2.5 件数

### 4.1 ブラウザ

- 確かめるための取引を、画面から作っておく：摘要が `=1+1`、`＝1+1`、`-1+2`、`+1+1`、`@SUM(1,1)`、`'abc`、カンマや `"` を含むもの〔例 `a,b"c`〕、絵文字を含むもの。科目で絞ると一部の行だけが出る、分けて登録したレシート〔例：食費 ＋ 日用品〕。**外のサイトの URL を含む式は使わない**。
- 取引一覧の「CSV で出力」を押す → ファイル名が `transactions-（今日の日付）.csv`。
- 絞り込んだ一覧〔予実比較の実績のリンクから入る、など〕から出す → 画面に出ている行と同じ行だけが、同じ並びで出る。
- 取引が 0 件の一覧、絞り込んで 0 件の一覧では、「CSV で出力」が出ない。

### 4.2 Google スプレッドシート

1. 新しい空のスプレッドシートを開く。
2. ファイル → インポート → アップロード → 出力したファイルを選ぶ。
3. 「インポート場所」は「新しいシートを挿入する」、「区切り文字の種類」は「自動的に検出する」、「**テキストを数値、日付、数式に変換する**」は「**はい**」にして、「データをインポート」。
4. 見る所：
   - 見出しの 1 つ目が「日付」で、前に変な文字がないこと。空いているセルに `=LEN(A1)` と入れて **2** になること〔3 なら BOM が残っている〕。
   - 日本語と絵文字が文字化けしないこと。
   - 金額が数として扱われ、`=SUM(F2:F○)` で合計できること。日付が日付として扱われること。
   - 摘要の `=1+1` などが、計算されずに文字のまま出ること。`'` が、セルに見えるか、数式バーにだけ見えるか。
   - カンマや `"` を含む摘要が、1 つのセルに入っていること。
   - 分割の列に、同じレシートの行は同じ番号が入っていること。
5. 同じファイルを、手順 3 で「**いいえ**」にして、もう 1 つ新しいシートに入れる。手順 4 と比べて、違いを書き留める〔`'` が見えるか、金額が文字になるか、など〕。
6. 〔013 の材料〕スプレッドシートから CSV で書き出して〔ファイル → ダウンロード → カンマ区切り形式〕、摘要の `'abc` などの `'` がどうなったかを見る。

## 5. 013 に送ること

CSV の取り込み〔[issue 013](../issues/013-CSVの取り込み.md)〕を決めるときの材料。どれも、今回は決めない。

1. **同じレシート**：同じ番号の行は、日付・取引先・支払方法が同じで、5 行まで〔要件定義書 5 章〕かを確かめる。**番号で組む**〔隣に並んでいるかどうかではない。表計算のアプリで並べ替えると、隣でなくなるため〕。ファイルの中で 1 行しかない組は、印なし〔「印がある ⇔ 2 行以上」。issue 032 の Q032-2〕。印は、保存のときにサーバーが新しく作る〔ファイルの番号を、そのまま印にしない。設計書 7.12 の S12〕。
2. **日付の書き方**：出力は `2026-11-22` の形だが、Excel で開いて保存し直すと、`2026/11/2` のような形になることがある〔推測。4.3 で確かめる〕。その形も受け付けるか。
3. **先頭の `'` を外す決まり**：先頭の `'` を 1 つ外して元に戻すのは、**このアプリが出したファイルをそのまま取り込むときだけ**成り立つ。スプレッドシートや Excel で保存し直したファイルは、`'` が外れていることがある〔例：摘要 `'abc` → 出力 `''abc` → スプレッドシートで保存し直すと `'abc` になる見込み → 取り込みで `'` を外すと `abc` になり、元の値から `'` が 1 つ消える〕。013 で、直したファイルを受け付けるかを決める材料にする。
4. そのほか〔調べた結果から〕：
   - Excel で保存し直すと、印が外れて、`=` で始まる値がそのまま入ることがある〔OWASP〕。取り込んだ値は文字として保存し、画面では `th:text` で出す〔今の決まりのまま〕。もう一度 CSV に出すときは、決まったこと 3 の印がまた付く。
   - 文字コード：スプレッドシートが書き出す CSV は、ふつう BOM なしの UTF-8〔2.6〕。Excel は、保存の形によって BOM 付きの UTF-8 か Shift_JIS〔推測〕。UTF-8 の BOM のあり・なしを両方受け付けるか、Shift_JIS も受け付けるか。
   - 読み取りを自作にするか、ライブラリを使うか〔2.7〕。
