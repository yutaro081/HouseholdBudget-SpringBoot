## 1. 目的

科目ごと・季節ごとの予算を設定できるようにします。次の5つがそろった状態にします。

- 予算設定画面（`/budgets?year=2026&season=spring`）が、設計書 2.2〜2.4、5.7 のとおりに動く。URL で季節を指定し、指定しないときは今の季節を表示する。範囲は2000年春〜2100年冬で、端では範囲外へのリンクを出さない。範囲外・不正な指定は 404。
- 入力欄の最初の値が、規則どおりに出る（その季節の予算があればその額、なければ直前に設定した季節の額、それもなければ0円）。**画面を開いただけでは行を作らない。** 保存したときに、その季節の全科目の行を作る・更新する（まとめて保存）。
- 1つでも入力エラーがあれば、何も保存せずに、入力値を残して表示し直す。送られた科目IDが自分のものか、同じIDが2回ないかを確かめる（他人・不正なら 404）。
- 予算額の入力は、Phase 5 の `StrictIntegerEditor` で読む。予算額は0円以上3,000,000円以下（0円は可、マイナスは不可）。
- 季節の計算（`SeasonPeriod`）に、期間・前後の季節・範囲の判定・URL の名前の変換を足し、単体テストで確かめる。Phase 7（予実比較）でも使う。

### 3.1 「ID と `user_id` の両方で絞る」型を、予算に当てはめる

| 層 | 決まり（Phase 4・5 と同じ） |
|---|---|
| Controller | `LoginUser.getUserId()` を、Service に必ず渡す。Form に `user_id` の項目を作らない（6.1）。年と季節は URL から受け取る |
| Service | メソッドの最初の引数は `userId`。科目は、`CategoryService` の `list(userId)` で自分のものを取り出して照らす。他人のID・存在しないID・同じIDが2回は `NotFoundException`（F3） |
| Repository | メソッドは、すべて `userId` を引数に取る。`findById` は、アプリのコードで使わない |

`BudgetRepository` に足す検索（名前は案。作るときに決める。方法は Q6-4 の決定による）：

| 検索（案） | 使う場面 |
|---|---|
| その季節の自分の予算を全件（`userId`、年、季節） | 表示の「その季節の予算があればその額」、保存の「作る・更新する」の判定 |
| 表示季節より前の自分の予算（初期値用） | 「直前に設定した季節の額」を、科目ごとに求める |

- 検索は、名前付きの検索かパラメータ付きの検索で書く。文字列を連結した SQL は書かない（7.4）。
- 季節の古い新しいは、**期間の順**（年、次に 春→夏→秋→冬）。DB の文字の順（`AUTUMN` < `SPRING` < `SUMMER` < `WINTER`）は、期間の順と違うので、並べ替えに使えない。

### 3.2 季節の URL と範囲（設計書 2.4。予算設定と予実比較に共通）

| 指定 | 結果 |
|---|---|
| `year`・`season` の両方なし | 今日（日本時間）が属する季節（冬は12月がある年。2027年2月は「2026年の冬」） |
| `year` が2000〜2100の整数、`season` が `spring`・`summer`・`autumn`・`winter` | その季節 |
| 片方だけの指定 | 404 |
| `year` が2000〜2100以外、数字でない | 404 |
| `season` が4つ以外 | 404 |

- 表示できる範囲は**2000年春〜2100年冬**。2000年春では「前の季節」を、2100年冬では「次の季節」を出さない（B15）。
- 前後の季節（2.4 の表）：春Y→前は冬(Y−1)・次は夏Y／夏Y→前は春Y・次は秋Y／秋Y→前は夏Y・次は冬Y／冬Y→前は秋Y・次は春(Y＋1)。
- 期間（5.8。開始日以上、終了日の翌日未満）：春Y＝Y/3/1〜Y/6/1、夏Y＝Y/6/1〜Y/9/1、秋Y＝Y/9/1〜Y/12/1、冬Y＝Y/12/1〜(Y＋1)/3/1。
- 見出し：「2026年 春（3月〜5月）」、冬は「2026年 冬（2026年12月〜2027年2月）」（2.3、2.4）。
- 「年と季節の指定の受け取り方、値のきびしさ、404 の判定の場所」は Q6-2 の決定による（予実比較も同じ決まりを使う）。

### 3.3 入力欄の最初の値と、「未設定」の印（設計書 2.3、5.7、Q23〜Q26）

科目ごとに、次の順で決める。

| 順 | 条件 | 最初の値 | 印 |
|---|---|---|---|
| 1 | その季節の予算が保存されている | その額 | なし |
| 2 | なければ、表示季節より前の季節のうち、その科目で予算が設定されている、**期間の順でいちばん近い**季節がある | その季節の額 | 「（この季節は未設定）」 |
| 3 | それもなければ | 0円 | 「（この季節は未設定）」 |

- 「直前」は期間の順で、表示している季節より前のうち、いちばん近いもの。**最後に保存した季節ではない**（Q23）。
- 行の並びは、自分の科目の登録順（`id` の順）。
- **画面を開いただけでは、行を作らない。** 保存すると、その季節の**全科目**の行が、表示どおりの額で作られる・更新される。初期値のまま変えなかった行も、その額で保存され、「未設定」の印は消える（Q25）。
- 印は、科目名の横に出す。見た目（薄い色の小さな文字など）は、`style.css` で付ける。
- 科目を追加すると、その時点の「今の季節」に予算0円の行ができる（Phase 4）。この行は**保存済みの行**なので、今の季節の画面では「0円、印なし」で出る。

具体例（今日が2026年10月29日＝2026年秋のとき）：

| 表示する季節 | 保存済みの行 | 食費の最初の値と印 |
|---|---|---|
| 2026年 秋 | 秋 30,000円（初期ユーザー） | 30,000円、印なし |
| 2026年 冬 | 秋 30,000円のみ | 30,000円、印あり（前の季節の額） |
| 2026年 夏 | 秋 30,000円のみ（夏より後の行は見ない） | 0円、印あり |
| 2027年 春 | 秋 30,000円、冬(2026) 50,000円 | 50,000円、印あり（直前＝冬） |
| 2026年 秋（科目を今日追加） | 追加した科目は秋 0円 | 0円、印なし |

### 3.4 入力チェックの一覧（設計書 6.2、6.5。予算額の1行ごと）

| 項目 | ルール | 場所 | メッセージ |
|---|---|---|---|
| 予算額 | 必須（空白だけも必須エラー） | F | 予算額を入力してください |
| | 整数（`StrictIntegerEditor`：半角の数字だけ、先頭の `-` は可。全角数字・途中の空白・`0x10`・`+5`・カンマ・小数・`10円` などは型変換のエラー） | F | 予算額は整数で入力してください |
| | 0以上3,000,000以下（0円は可、マイナスは不可） | F（D の CHECK も） | 予算額は0円以上3,000,000円以下で入力してください |
| 科目ID | 自分の科目。同じIDが2回ない | S | （404 画面） |
| 年・季節（URL） | 3.2 のとおり | S またはC | （404 画面） |

- 型変換のエラーのときは、範囲のメッセージを出さない（G3）。「必須」を他のエラーと重ねない（D4 の B）。
- **1つでもエラーがあれば、何も保存しない**。エラーのある行の横にメッセージを出し、**全行の入力値を残す**（6.9）。
- 送られなかった科目の、その季節の予算は変えない（F2）。

### 3.5 境界値（完了条件の確認表）

| 項目 | 保存できる | エラーになる |
|---|---|---|
| 予算額 | 0、1、3,000,000 | -1、3,000,001、空、空白だけ、`abc`、`1,000`、`１２３`（全角）、`1 000`、`0x10`、`+5`、`1.5`、`10円`、`99999999999` |
| 年 | 2000、2100 | 1999、2101、`abc`、空、`2026.5`、`02026`、`+2026`（Q6-2 の決定による） |
| 季節 | `spring`、`summer`、`autumn`、`winter` | `Spring`（大文字）、`xyz`、空（Q6-2 の決定による） |
| 指定の組み合わせ | 両方あり／両方なし | 片方だけ |
| 科目ID | 自分のID（重複なし） | 他人のID、存在しないID、同じIDが2回、数字でない値、空（Q6-3 の決定による） → 404 |
| 範囲の端 | 2000年春（前なし）、2100年冬（次なし）を表示できる | 1999年冬、2101年春は 404 |

- DB の CHECK 制約も、同じ境界で拒否することを、Repository のテストで確かめる（金額 -1／3,000,001、年 1999／2101）。一意制約が、同じ `(科目, 年, 季節)` の2行目を拒否することも確かめる。

#### 行ごとの金額への変換の登録（Q6-1。この手順のうちに実験する）

Phase 5 では、Controller の `@InitBinder` で、金額の項目の名前を指定して `StrictIntegerEditor` を登録した。予算は科目ごとの行が並ぶので、項目の名前が `rows[0].amount`、`rows[1].amount`、… になる。**登録の仕方で、行ごとに変換が効くか**を、実験で確かめる（Phase 5 と同じ書き方：Spring の起動なしの束縛のテスト）。
