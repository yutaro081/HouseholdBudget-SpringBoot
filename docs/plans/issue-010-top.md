## 1. 目的と、決まっている形

ログインしたあとに開く**「トップ」画面**を作ります。今の季節と今週の使い方が、メーターと円グラフで一目で分かるようにします。**JavaScript もライブラリも使わず、HTML と CSS だけ**で描きます。

**決まっている形**（あなたが決めた。この手順書では、変えません）

- メニューの**先頭**に「トップ」を足す。**ログインしたあとはトップに移る**〔今は取引一覧〕。
- 画面の**右上**に「予実比較を見る」と「取引を登録」。
- 上から順に：
  1. **季節のメーター**：今の季節の合計だけ。「使った額 / 予算」「残り」を 1 円単位で。棒は「予算に対する使った割合」、縦の線は「今日」〔季節の何 % まで日が進んだか〕。
  2. **今週の円グラフ**：使っていない科目は出さない。真ん中に今週の合計。横に科目・金額・割合の一覧。色はターコイズの濃淡と灰色だけ〔赤・青・💮 の色は使わない〕。CSS の `conic-gradient`。
  3. **今週の科目ごとのメーター**：科目ごとに「今週の実績 / 週の予算」の棒と、縦の線「今日」〔週の何日目か〕。いちばん上に合計の行。
- **計算の決まり**

| 項目 | 決まり |
|---|---|
| 今週 | 日曜〜土曜。季節をまたぐ週は、前の季節の取引もそのまま入れる |
| 週の予算 | 「今日が入っている季節」の科目の予算 ÷ 13 を、100 円単位で切り上げ |
| 今週の実績 | 100 円単位で切り上げ〔円グラフもメーターも〕。円グラフの割合も、切り上げた額から出す |
| 合計 | 予算も実績も、科目ごとに切り上げた額を足したもの |
| 今週の色 | 予実比較と同じ決まり〔赤：超過、青：1/3 以下、💮：1/3 を超えて予算以下、予算 0 円なら色なし〕を、週の予算に当てはめる。判定は、画面に出ている切り上げ後の額で行う |
| 言葉 | 「今週の」「週の予算」と書く〔予実比較と混ざらないため〕 |
| 見た目 | issue 015 の決まり〔色・フォント・角の丸み〕。💮 の行の背景は `#FFF2E5` |

**計算の例**（この手順書の説明で使う）

- 週の予算：科目の予算 30,000 円 → 30,000 ÷ 13 ＝ 2,307.69… → 100 円単位で切り上げて **2,400 円**。式にすると「予算 ÷ 1,300 を切り上げて、100 を掛ける」〔整数だけで計算できる〕。
- 今週の実績：実績 1,234 円 → **1,300 円**。0 円は 0 円のまま。
- 今日が 2026年11月8日〔日曜〕なら、今週は 11月8日〜11月14日。日曜が 1 日目、土曜が 7 日目。今の季節は秋〔9月1日〜11月30日の 91 日間〕で、11月8日は 69 日目〔69 ÷ 91 ＝ 約 76 %〕。

### 3.3 見つかった食い違い・注意（あなたに知らせたいこと）

1. **一言は出さない**〔Q010-3 で決定〕：季節のメーターの下の一言は、予実比較に足す予定の「着地見込み」と中身が重なり、要件定義書 9 章の「アラート機能」とも近い。一言を出す場所は、次の回の「きょうのひとこと」〔「グラフへのひとこと」を含む〕にまとめる。**要件定義書 9 章は直さない**。
2. **色のテストと設計書の食い違い**：設計書 2.3 の色の表は、`#0E9594`〔基本のターコイズ〕を「文字を乗せない所〔棒、ロゴの地、金額の欄の枠など〕」に使ってよいとする。一方、`ColorSchemeStyleSheetTest`〔#11〕は、issue 015 の 3 回目で「枠〔`border`〕だけ」に絞った。棒や円に使うなら、**テストを直すか、棒・円用の別の色の変数を作る**必要がある。→ Q010-9。
3. **実績が 0 円の行は、青になる**：予実比較の決まり〔③ 実績の 3 倍が予算以下なら青〕は、実績 0 円も含む。「予実比較と同じ決まり」を週にそのまま当てはめると、**今週まだ使っていない科目は、予算があれば青い行**になる〔週の初めは、ほとんどの行が青〕。予実比較でも、使っていない科目は青い行なので、同じ見え方。あなたの意図どおりか確かめたい。→ Q010-13。
4. **週の途中で週の予算が変わる**：週の予算は「今日が入っている季節」で決まるので、季節の境目〔例：11月30日と12月1日〕をまたぐ週は、**日付が変わると、週の予算が秋の予算から冬の予算に変わる**。実績は、前の季節の取引も入れたまま。決まったとおりに作るが、画面の説明に「今日が入っている季節の予算」と書くか、あなたに確かめたい〔Q010-6 の下の補足〕。
5. **合計は、少し多めに出る**：科目ごとに 100 円単位で切り上げて足すので、合計は、元の額の合計より、最大で「99 円 × 科目の数」多くなる。予算の合計も同じ〔3 科目で 30,000 円ずつなら、週の予算の合計は 2,400 × 3 ＝ 7,200 円。90,000 ÷ 13 ＝ 6,923 円を 100 円単位で切り上げた 7,000 円より多い〕。決まったとおりで、間違いではない。
6. **`ComparisonRow` は使い回さない**：科目の ID がないので、週の予算を作れない。変えると予実比較のテストにも広がるので、トップ用の Service が科目・予算を自分で取る。科目の一覧を `ComparisonService` と二重に読む〔検索が数回増えるだけ。件数は最大 256 科目〕。
7. **「合計」の予算が、未設定の科目を含まない**：予実比較と同じく、季節の予算が未設定の科目は、合計の予算に足さない。ただし、実績は全科目を足す〔予実比較の合計行と同じ〕。週の合計も同じ決まりにする案〔Q010-7〕。
