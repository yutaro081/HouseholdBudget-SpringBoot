## 1. 目的

画面の文字を、**Zen Kaku Gothic New**（日本語のゴシック体）にそろえます。次の 4 つがそろった状態にします。

- フォントのファイルが、**アプリの中**（`static/fonts/`）にあり、外のサーバー（CDN）からは何も読まない。
- **ログイン画面を含む全画面**で、文字のフォントが Zen Kaku Gothic New になる（ログイン前でもフォントが読める）。
- ライセンス（SIL OFL）の条件を守っている（著作権表示とライセンス全文を、フォントと一緒に配る）。
- 画面を開くたびに、1 MB 前後のフォントを取り直すことがない（Q15-8）。

### 3.2 ライセンス（SIL Open Font License 1.1）

- 配布元の `OFL.txt` は、**著作権表示**「Copyright 2022 The Zen Kaku Gothic Project Authors (https://github.com/googlefonts/zen-kakugothic)」と、ライセンス全文（OFL 1.1）。**Reserved Font Name（改変版に使えない名前）の指定は、ない**。
- **注意（食い違い）**：フォントのファイルの中の著作権表示（name テーブル）は「Copyright 2022 **The Zen Project Authors** (…)」で、`OFL.txt` は「**The Zen Kaku Gothic Project Authors**」。**同梱するのは、`OFL.txt` のとおり**にし、食い違いがあることを `THIRD-PARTY-NOTICES.md` に一言書く、のがおすすめ。
- 条件（要点）：①フォント単体で**売らない**。②アプリと一緒に配る（再配布する）ときは、**どのコピーにも、著作権表示とライセンス全文を付ける**〔別ファイルでよい〕。③Reserved Font Name は指定がないので、名前の制限はない。④作者の名前で、改変版を宣伝しない。⑤フォントは**OFL のまま**配る〔別のライセンスにしない。アプリ本体のライセンスには影響しない〕。
- **woff2 への変換・文字の絞り込みは、OFL では「改変版（Modified Version）」**〔定義に「形式を変える」が入る〕。ただし、Reserved Font Name がないので、**名前を変える必要はない**。条件②〔表示の同梱〕は、同じように必要。
- **`THIRD-PARTY-NOTICES.md` に書くこと**：Bootstrap の節と同じ形で、名前・版・含んでいるファイル・出どころ・ライセンス（OFL 1.1）・確かめた方法（SHA-256）・**著作権表示**・**ライセンス全文**。変換したなら、**変換の方法と道具の版**〔下の 3.3〕も書く。

### 3.4 軽くする方法（サブセット化）の手間と注意点

- **全部の文字を 1 ファイルにしても、1 つ約 1 MB**。このフォントは、もともと 7,737 文字だけで、**絞っても 7% しか減らない**。大きな節約にはならない。
- **使う文字だけに絞る**〔画面の文言だけ〕と、数十 KB になる。ただし、**科目名・摘要・取引先名は利用者が自由に入力する**ので、絞った外の文字は、システムのフォントに切り替わって、**文字ごとに字形が混ざる**。要件定義書 5 章は文字の種類を絞っていない。
- **分割して、使う分だけ取る**〔Google Fonts や Fontsource の `unicode-range` の方法〕：ブラウザが必要な分割ファイルだけ取る。ただし、**1 つの太さで 118 ファイル（240 ファイル）をリポジトリに置く**ことになり、`400.css` も 108 KB で大きい〔CSS が `no-store` だと毎回取り直し〕。入門者の学習用のリポジトリには重い。
- **自分で絞る・変換する手間**：①Python の fonttools と brotli が要る〔道具の版を記録する〕。②**絞り方（残す文字）と、コマンドを、手順書に記録する**〔あとで同じファイルを作り直せるように〕。③OFL では改変版〔名前はそのまま〕。④字形が合っているか、ブラウザで見て確かめる。⑤撮り直すたびに、バイナリが Git の履歴に残る〔`.gitattributes` に、バイナリとして扱う指定を足す〕。
- **結論（案）**：**全部の文字を、太さ 2 本、woff2 の 1 ファイルずつ**（合わせて約 2.1 MB）。絞らない。大きさは、**キャッシュで補う**（Q15-8）。

### 3.5 キャッシュ（`Cache-Control: no-store`）と、`/fonts/**` の許可

**実際の応答のヘッダーで確かめた**〔`.\mvnw spring-boot:run` で起動して `curl`。確かめたあと、起動したアプリは止めた〕：

| 取った URL | 状態 | `Cache-Control` |
|---|---|---|
| `/login`（画面） | 200 | `no-cache, no-store, max-age=0, must-revalidate`（+ `Pragma: no-cache`、`Expires: 0`） |
| **`/css/style.css`** | 200 | **同じ `no-cache, no-store, max-age=0, must-revalidate`** |
| **`/css/bootstrap.min.css`**（232,111 バイト） | 200 | **同じ** |
| **`/js/back-reload.js`** | 200 | **同じ** |
| `/fonts/test.woff2`（まだ存在しない） | **302 → `/login`** | `no-store`〔ログインが要る〕 |

- **静的ファイル（CSS・JavaScript）にも `no-store` が付いている**。→ **フォントも、置き方をそのままにすると、画面を開くたびに約 2 MB を取り直す**。Bootstrap の CSS（232 KB）も、今は毎回取り直している。
- **`/fonts/**` は、今は許可されていない**〔302 でログイン画面に飛ぶ〕。ログイン画面もフォントを使うので、**`SecurityConfig` の `permitAll` に `/fonts/**` を足す必要がある**〔`/css/**`、`/js/**` と同じ。設計書 2 章、7.2、7.3〕。
- **直し方を試した**〔設定を足さず、起動時の引数だけで確かめた〕：`--spring.web.resources.cache.cachecontrol.max-age=3600` を付けて起動すると、**`/css/style.css` の応答は `Cache-Control: max-age=3600` だけ**になり、`no-store` は消えた。**画面 `/login` は、`no-store` のまま**。つまり、**Spring MVC が静的ファイルに `Cache-Control` を付けると、Spring Security は上書きしない**〔画面の `no-store` は残る〕。
  - ただし、この設定は `/css/**` と `/js/**` も同じに覚えさせる〔`style.css` を直したのに画面が変わらない、が起きる〕。→ **`/fonts/**` だけ**に付ける方法が要る〔`WebMvcConfigurer` の `addResourceHandlers("/fonts/**")` で `CacheControl` を指定する。実装は 5.5 で確かめる〕。
- **自動テストの現状**：`SecurityBehaviorTest` が「ログインなしで開ける URL」〔`/login`、`/register`、`/css/…`、`/js/back-reload.js`〕を確かめている。`CacheControlHeaderTest` は、画面の `no-store` だけを確かめている。

## 8. つまずいたとき

| 起きたこと | 原因の候補 | 対処 |
|---|---|---|
| ログイン画面でフォントが変わらない | `/fonts/**` が許可されていない〔302 でログイン画面が返る〕 | `SecurityConfig` の `permitAll` に `/fonts/**` を足す。Network で、フォントの応答が 200 か 302 か見る |
