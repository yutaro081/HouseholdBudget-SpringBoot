## 1. 目的

他の人（採用担当者など）が見て、**何を作ったか・どう作ったか・どう動かすか**が分かる状態にします。このアプリは、コードを読まない人にも、README と画面の画像で伝わるようにします。次の6つがそろった状態にします。

- **README**：概要、作った目的、主な機能、画面の紹介、使用技術、設計と工夫、セキュリティ、テスト、仕様駆動開発と AI の使い方、既知の制限と今後の予定、起動方法。**まっさらな環境で、README の手順どおりに起動できる**ことを確かめる。
- **画面の画像**：主要な画面を撮り、README に載せる。**画像に、パスワード・接続先・個人の情報が写っていない**ことを、載せる前に確かめる。

- **面接前のリハーサル**：iPad の Safari で、アプリを開いて触る。Phase 8 から引き継いだ確認（ログアウト後の「戻る」、💮 と薄い緑の背景、「今の季節」ボタンの折り返し、4.13 の項目）を行う。
- **設計書・要件定義書・実行計画書が、実際に作ったものと合っている**。
- **振り返り**を書く。`main` に取り込み、完成のタグを付けて GitHub に push する（Git の操作は、あなたが行う）。

## 7. つまずいたとき

| 起きたこと | 原因の候補 | 対処 |
|---|---|---|
| 撮った画像に、ユーザー名や個人の情報、パスワード、接続先、アドレス欄が写っていた | 撮り方の選び間違い、`test1` などで撮った | その画像を**コミットしない**。`demo` の画面で撮り直す。すでにコミットしてしまったときは、**そのままにせず**、先に報告する（履歴の扱いは、あなたが決める） |

| Mermaid の図が表示されない | 書き方の誤り、GitHub の対応外の記法 | GitHub で表示を確かめる。単純な記法に直す |
| 予実比較で 💮 が出ない／赤にならない | デモ用データの金額・季節の入れ間違い | 3.3 の表と、取引の日付〔季節の境目〕を見直す。予算設定の保存を忘れていないか |
