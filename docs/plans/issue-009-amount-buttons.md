## 1. 目的

金額の入力を、今より楽にします。次の 3 つがそろった状態にします。

- **足すボタン**（+1・+10・+100・+1,000・+10,000）で、金額の欄の数を増やせる。
- **消費税のボタン**（×1.1 と ×1.08）で、欄の数（税抜）を、税込みの金額に変えられる。
- **ボタンを使わなくても、手で数字を打てば、今までどおり使える**。JavaScript が無効のブラウザでも同じ。**サーバー側の入力チェックは、今のまま**（ボタンで入った値も、手で打った値と同じ決まりで確かめる）。

**この機能は、JavaScript が要る**（欄の値をブラウザの中で変えるため）。Phase 9 まで、自作の JavaScript は「削除の確認」と「戻る」の対策だけだった。**JavaScript を使う決まりは、本人の判断でゆるめてよい**〔issue 008・009 に記録済み〕。ただし、**決まりを変えるのは、機能を実際に作るときに、要件定義書・設計書から行う**（この手順書の 4.3）。

### 3.1 ボタンの動き（案。Q009 の決定で変わる）

| ボタン | 欄が `1200` のとき | 動き |
|---|---|---|
| +1・+10・+100・+1,000・+10,000 | `1201`・`1210`・`1300`・`2200`・`11200` | 欄の数に足す。欄が空なら、0 として足す〔Q009-9〕。ボタンの**文字**はカンマ付き。`data-amount-add` の値は数字だけ |

- **消費税のボタンの「押せる・押せない」**（Q009-3 の決定）：消費税のボタンを押すと、欄を税込みにして、**消費税の 2 つのボタンを押せなくする**。**足すボタンを押して金額を変えても、押せないまま**。押せるようになるのは、**欄を手で書き換えたとき**と、**欄を空にしたとき**だけ〔**クリアのボタンは、欄を空にするので、押せるようにする**。ボタンが値を書き換えても `input` イベントは起きないので、クリアのボタンの処理の中で、押せるようにする処理を**直接呼ぶ**。クリア以外のボタンが書き換えた値は、「手で書き換えた」ことにはしない〕。税込みの金額に、もう一度税をかけないため。登録画面の最初は、押せる。**画面を開いたとき、欄に値が入っていれば、最初は押せない**〔その金額が、すでに税込みかもしれないため。編集画面と、入力エラーで表示し直した画面の、両方。欄が空なら押せる。Q009-18。もとの Q009-15 の (a) は、編集画面だけだった〕。押せないときは、**固定の文**「この金額には、もう税をかけられません。税抜きの金額を入れ直すと、押せるようになります。」を、ボタンの近くに出す〔Q009-15 の (b)。文は HTML に書いてあり、JavaScript は見せる・隠すだけ〕。
- **ボタンは `type="button"`**（送信しない）。Enter キーで、ボタンが押されない。
- **計算は整数だけで行う**（小数を使わない。例：`Math.floor(n * 110 / 100)`）。`1.1` を掛けると、小数の誤差で、端数がずれることがあるため。
- 欄に、数字（全角を含む）以外が入っているとき〔`1,200`、`12円`、空白だけ、など〕は、**何もしない**〔Q009-9〕。サーバーが、今までどおり、エラーにする。
- 計算のあとの欄は、**数字だけ**〔カンマを付けない〕。

## 7. つまずいたとき

| 起きたこと | 原因の候補 | 対処 |
|---|---|---|
| ボタンを押すと、登録されてしまう（画面が移動する） | ボタンが `type="button"` でない〔`<button>` の標準は送信〕 | `type="button"` を付ける |
| ボタンを押しても何も起きない | JavaScript が読み込まれていない〔`th:src` の書き間違い、`defer`〕／`data-` 属性の書き間違いで、欄が見つからない／JavaScript のエラー | ブラウザの開発者ツールの Console を見る。Network で、`/js/…` が 200 で返っているか |
| 予算の行などで、別の欄が変わる | 欄を `id` で決め打ちしている〔`th:field` の `id` は、行ごとに違う〕 | ボタンの `data-` 属性で、対象の欄を指す〔4.5〕 |
| 税込みの金額が 1 円ずれる | 小数で計算している〔`n * 1.1`〕／端数の決まりが違う | **整数だけ**で計算する〔`n * 110 / 100` の切り捨て〕。3.2 の表と見比べる |
| 税込みを 2 回押して、金額が増えすぎる | Q009-3 の対策がない | Q009-3 の決定のとおりに直す |
| ボタンを押しても、`1,200` が変わらない | 数字以外が入っている。Q009-9 のとおり、何もしない | 数字だけに直してから押す。サーバーも、カンマを受け付けない〔今までどおり〕 |
| iPad で、ボタンを押すとページが拡大される | 連続タップ〔ダブルタップ〕で拡大される | ボタンの間隔を広げる。`touch-action: manipulation` を、そのボタンに指定する〔CSS を最小限に足す。先に報告〕 |
| 画面を更新すると、ボタンの状態が戻る | 状態を、ブラウザが覚えている〔`disabled`〕 | 欄の値と、ボタンの状態を、ページを開いたときに、そろえる〔欄の値が空でなくても、押せる状態から始める、など。Q009-3 の決定による〕 |
| JavaScript を無効にすると、ボタンが出たままになる | `hidden` を付け忘れた／CSS で `display` を上書きした | Q009-11 の A のとおり、`hidden` を付ける。Bootstrap の `d-flex` が `hidden` を上書きしていないか |
| `SecurityBehaviorTest` が落ちる | `/js/**` の許可を変えた | 今の許可〔`/js/**`〕を変えない |
| `th:utext` のテスト〔`TemplateSafetyTest`〕が落ちる | `th:utext` を使った | `th:text` にする。ボタンの文字は固定で、`th:utext` は要らない |
