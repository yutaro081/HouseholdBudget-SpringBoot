## 1. 目的

季節ごとの、科目別の「予算・実績・差額」を表示し、色分けする。このアプリの最大の特徴です。次の6つがそろった状態にします。

- 予実比較の画面（`/comparison?year=2026&season=spring`）が、設計書 2.3、2.4、5.9 のとおりに動く。URL で季節を指定し、指定しないときは今の季節を表示する。範囲は2000年春〜2100年冬で、端では範囲外へのリンクを出さない。範囲外・不正な指定は 404（予算設定と同じ決まり）。
- 色の判定（`BudgetColorJudge`）が、要件 4.4 の順番どおりに動く。単体テストで、設計書 5.9 の表の例をすべて確かめる。
- 期間内の科目ごとの実績（取引の合計）を、`user_id` と期間（開始日以上、終了日の翌日未満）で絞って集計する。取引がない科目は0円。
- その季節の予算が未設定の科目は、予算「未設定」・差額は空欄・色なし。
- 合計行：合計の予算＝設定済みの科目の予算の合計、合計の実績＝全科目の実績の合計、差額＝その差。色は各行と同じ判定。全科目が未設定のときだけ、合計行も予算「未設定」・差額は空欄・色なし。
- メニューに「予実比較」を足す（これで設計書 2.3 のメニューがそろう）。

### 3.2 季節の URL と範囲（設計書 2.4。予算設定と同じ決まり）

| 指定 | 結果 |
|---|---|
| `year`・`season` の両方なし | 今日（日本時間）が属する季節（冬は12月がある年） |
| `year` が2000〜2100の整数、`season` が `spring`・`summer`・`autumn`・`winter` | その季節 |
| 片方だけ、`year` が範囲外・数字でない、`season` が4つ以外・大文字・空 | 404 |

- 表示できる範囲は2000年春〜2100年冬。2000年春では「前の季節」を、2100年冬では「次の季節」を出さない（B15）。
- 年と季節の判定は `SeasonPeriod.parse`（Q6-2）。Controller で、両方なしなら `SeasonPeriod.from(今日)`、それ以外は `parse` の結果が空なら `NotFoundException`。`BudgetController.resolve` にある 6 行を、**共有の部品に取り出し、`BudgetController` も `ComparisonController` も同じ部品を使う**（Q7-1。予算設定と予実比較で URL の決まりが食い違わないようにするため）。部品の置き場所と名前は案：`domain` の `SeasonPeriod` に、「年・季節の文字列と今日から季節を決める。不正なら空」を返す静的メソッドを足す（Spring に頼らないので、単体テストで境界を確かめられる）。404 にするのは、これまでどおり Controller（`NotFoundException`）。
- 見出しと前後リンクは `fragments/season.html` の `nav(period, previous, next, path)`。`path` は `'/comparison'`。
- 未来の季節も表示できる（実績は0円）。取引の日付の下限は 2000年3月1日（2000年春の初日）なので、入力できる取引は、すべて表示できる季節に入る（R15、issue 003、4.4 のあとで入った直し）。

### 3.3 実績の集計（設計書 5.8、5.9、4.6）

- 期間：`SeasonPeriod.startDate()` 以上、`endDateExclusive()` 未満（「日付 ≧ 開始日 かつ 日付 ＜ 終了日の翌日」）。冬は翌年の3月1日の前日まで。うるう年の2月29日は前の年の冬。
- 絞り込み：`user_id`（自分の取引だけ）と期間。
- 返すもの：科目ID と合計（`CategoryActual`）。取引がない科目の行は返らない → Service が、自分の全科目について、行がなければ0円にする。
- 合計は `Long`（1件最大100万円、件数に上限がないので `INT` を超えうる、3.1）。
- 検索の書き方（`@Query` を使うか）は Q7-3 の決定による。文字列を連結した SQL は書かない（7.4）。集計の検索には `@EntityGraph` は要らない（科目のIDと合計だけを返す。実行計画書）。

### 3.4 予算が未設定の扱い（設計書 2.4、5.9、R11）

- その季節の `budgets` の行がない科目が「未設定」。「未設定」と「0円」は別（0円は設定済みで、実績があれば赤）。
- 取得は `BudgetRepository.findByUserIdAndSeasonYearAndSeason`。**予算設定画面の「前の季節の額を最初の値にする」（印つき）は入力欄の初期値だけの決まりで、予実比較には使わない。** 行がなければ、前の季節の額があっても「未設定」。

| 行の状態 | 予算の欄 | 実績の欄 | 差額の欄 | 色 |
|---|---|---|---|---|
| 予算が設定済み | 予算の額 | 合計（なければ0円） | 予算 − 実績（超過はマイナス） | 3.5 の判定 |
| 予算が未設定 | 「未設定」 | 合計（なければ0円）。表示する | 空欄 | なし |

### 3.5 色の判定（設計書 5.9、要件 4.4。各行も合計行も同じ）

予算が未設定なら、色なし。設定されていれば、次の順番で判定する（順番は変えない）。

| 順 | 条件 | 結果 |
|---|---|---|
| ① | 実績 ＞ 予算 | 赤（予算が0円でも、実績があれば赤） |
| ② | 予算 ＝ 0円 | 色なし（実績も0円のとき。③を通すと 0 ≦ 0 で青になってしまうので、先に除く） |
| ③ | 実績 × 3 ≦ 予算 | 青（ちょうど1/3も青） |
| ④ | それ以外 | 色なし |

- 計算は `Long` で行う（`実績 × 3` が `INT` を超えないように、3.1）。

**単体テストに入れる例**（設計書 5.9 の表の9行。実行計画書の完了条件の表と合わせる）：

| 予算 | 実績 | 色 | 理由 |
|---|---|---|---|
| 30,000円 | 30,001円 | 赤 | ① 超過 |
| 30,000円 | 30,000円 | 色なし | 超過ではない。③ 90,000 ≦ 30,000 は成り立たない |
| 30,000円 | 10,000円 | 青 | ③ 30,000 ≦ 30,000（ちょうど1/3） |
| 30,000円 | 10,001円 | 色なし | ③ 30,003 ≦ 30,000 は成り立たない |
| 30,000円 | 0円 | 青 | ③ 0 ≦ 30,000 |
| 0円 | 1円 | 赤 | ① 予算が0円でも、実績があれば赤 |
| 0円 | 0円 | 色なし | ② |
| 未設定 | 5,000円 | 色なし | 予算が未設定 |
| 未設定 | 0円 | 色なし | 同上 |

### 3.6 合計行（設計書 2.4、5.9、Q22 の C）

| 項目 | 決まり |

### 3.7 表示の形と色を付ける場所

- 金額：`30,000円`。差額のマイナスは `-5,000円`。Thymeleaf の標準の書き方（`#numbers.formatInteger(値, 1, 'COMMA')` ＋「円」）を画面に書く。整形のクラスは作らない（Q5-9）。**負の数と0がどう出るかを、作るときに確かめる**（実行計画書：Phase 5 から引き継ぐこと）。
- 色（F4）：**その行の文字全体**（科目名・予算・実績・差額）に付ける。数字だけには付けない。合計行も同じ。赤・青・色なしの3通り。具体的な色の値は Q7-6 の決定による。
- 表の列：科目、予算、実績、差額。最下行が合計行。行の並びは科目の登録順（`id` の順）。
- 画面の値は `th:text` で出す。`th:utext` は使わない（7.5）。

| 予算0円・実績0円が青になる | ②が③より後ろにある／②がない | 順番は ①→②→③（3.5）。単体テストの「0円・0円」で確かめる |
| ちょうど1/3（30,000円と10,000円）が青にならない | `実績 × 3 ＜ 予算` にしている | `≦`（以下）にする。単体テストの境界で確かめる |
| 予算が未設定の科目が「0円」で出る／赤になる | `null` を0円として扱っている | 「未設定」と「0円」は別（3.4）。判定に `null` を渡す前に0へ直していないか確認する |
| 予算の行がない季節に、前の季節の額が出る | 予算設定画面の初期値の規則（`BudgetService.edit`）を使っている | 予実比較は `findByUserIdAndSeasonYearAndSeason` の結果だけを見る（3.4） |
| 取引がない科目が表に出ない | 集計の結果だけから行を作っている | 自分の全科目から行を作り、実績がなければ0円にする（3.3） |
| 合計の実績が、予算が未設定の科目の分だけ足りない | 設定済みの科目の行だけを足している | 合計の実績は**全科目**の実績（3.6）。合計の予算だけが設定済みの科目 |
| 合計行が、一部の科目だけ未設定でも「未設定」になる | 「全科目が未設定」でなく「1つでも未設定」で判定している | 設定済みの科目が1つでもあれば、合計の予算を出す（Q22 の C、3.6） |
| 差額のマイナスが `--5,000円` や `5,000円-` になる | 「円」を付ける式と、符号の式が重なっている | 負の数の出方を、`#numbers.formatInteger` で先に確かめる（3.7） |
| 画面が 500（`LazyInitializationException`）になる | 科目名など、画面が読む関連を `ComparisonResult` に入れていない | 科目名は文字列にして `ComparisonRow` に入れて渡す。ブラウザで確かめる（自動テストでは見つからない、実行計画書 ルール8） |
| 合計が大きいときに、数がおかしくなる | `int` で足している | 合計も `実績 × 3` も `Long`（3.1、3.5） |
| 色が行の一部（数字だけ）にしか付かない | クラスを `td` の中の数字の `span` に付けている | `tr` に付けて、中の文字が引き継ぐようにする（F4） |
| 年と季節の指定が、予算設定と違う動きをする | 判定を別に書いた | `SeasonPeriod.parse` と、両方なしだけ今の季節、の決まりを使う（3.2） |
| `.\mvnw test` のあと、`transactions`・`budgets` にテストの行が残る | トランザクションで包んでいないテストがある | 各テストを `@Transactional` にする（Phase 3 の Q3-8） |
| パスワードをコミットしてしまった | — | ファイルを消すだけでは履歴に残る。**そのパスワードを変更してから**、相談する（7.9） |
