# 021：お知らせ（alert）の色を、アプリの色にそろえる（候補）

> **状態（2026年11月11日）**：☐ **候補**〔調べた結果の一覧だけ。**直すのは別の機会**。要件定義書・設計書・コードは、まだ変えていない〕。

## 概要

画面の「お知らせ」の枠〔Bootstrap の `alert`〕のうち、**黄（`alert-warning`）・緑（`alert-success`）・赤（`alert-danger`）は、Bootstrap の標準の色のまま**。アプリの色〔ターコイズ、設計書 2.3「色の決まり」〕とそろっていない。特に **`alert-danger` の赤は、エラーの赤 `#B02A37`（入力エラーの文字・削除ボタン）と違う**〔お知らせの文字 `#58151C`、地 `#F8D7DA`、枠 `#F1AEB5`〕。

issue 019 のブラウザの確認で、「Bootstrap の青が残っていないか」を調べたときに分かった〔青は 1 か所〔複写のお知らせ `alert-info`〕だけで、そこは issue 019 の中で直した〕。

調べて、問題のなかったもの：`btn-primary`〔`style.css` でターコイズに上書き済み〕、リンクの色、入力欄の枠、`btn-outline-secondary`、`btn-outline-danger`、`bg-body-tertiary`〔ヘッダーの帯。白に上書き済み〕。予実比較・トップの青 `#1565C0` は、「予算の 1/3 以下」の意味の色なので、そのまま残す。

## 決めること（この issue を進めるとき）

- 4 種類〔成功・失敗・案内・複写のお知らせ〕を、**どの見た目にそろえるか**。案：複写のお知らせと同じ「白い地、左 4px の線、本文の色」で、線の色だけ変える〔成功＝ターコイズ、失敗＝エラーの赤 `#B02A37`、案内＝補足の灰色〕。色だけに頼らず、文でも分かる〔今も文で書いてある〕。
- 失敗のお知らせの赤を、エラーの赤 `#B02A37`〔背景 `#F6F8F8` の上で 6.09 対 1〕に**そろえるか**。そろえる場合は、設計書 2.3 の色の表と、`ColorSchemeStyleSheetTest` に足す。
- 緑・黄の標準の色を、アプリの色の決まり〔設計書 2.3〕に**入れるか、やめるか**。
- 文字と地の明るさの比は、4.5 対 1 以上〔issue 015 の目安〕。
