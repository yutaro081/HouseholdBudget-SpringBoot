# 007：予算設定と予実比較に、「今の季節」に戻るリンクを足したい

## 概要

予算設定（`/budgets`）と予実比較（`/comparison`）で、ほかの季節を見ているときに、ワンクリックで「今の季節」へ戻れるリンクを足したい、という要望。**表示と操作の追加だけ**で、Controller・Service・URL の決まりは変えない。**要件定義書にない画面の部品**だが、要件 4.3・4.4 の「季節を指定せずに開いたときは今の季節を表示する」を、リンクで開けるようにするだけなので、要件定義書は直さない案（調べた結果は下）。

## 要望の内容

- 要望：年と季節を選ぶ欄（Phase 8 の G1）や「前の季節」「次の季節」で別の季節へ移ったあと、「今の季節」へ一度で戻りたい。
- 理由：今は、メニューの「予算」「予実比較」を押し直せば今の季節に戻れるが、画面の中に戻り先がなく、分かりにくい。遠い季節を見たあとに、年と季節の選択を手で合わせ直さなくて済むようにしたい。
- 足す場所：`fragments/season.html`（予算設定と予実比較で共有する部品）。1か所に足せば、2つの画面に同時に入る。
- 行き先：**季節を指定しない URL**（`/budgets`、`/comparison`）。部品にはすでに引数 `path` があり、リンクの先は `@{${path}}` で作れる。`SeasonPeriod.resolve` と Controller は変えない（季節を指定しない URL は、今の季節を表示する。要件 4.3・4.4、設計書 2.4）。
- **今の季節を見ているときも出す**（隠さない）。理由：画面の部品が、今見ている季節が「今の季節」かどうかを判定しなくてよい。判定を足さないので、Controller・Service・テストの前提を変えずに済む。
- **Phase 8 の中で、issue 005（💮）と一緒に行う。画面の画像（Phase 9）の前。**

## 決定（2026年11月2日。あなたが決めた）

- **ラベルの文言**：「今の季節」。
- **置く場所**：「前の季節」「次の季節」と**同じ行の真ん中**。見出し（年と季節）もその行にあるので、見出しとの並び（見出しの前後・上下）は、実装のときに画面で確かめて決める。
- **見た目**：前後のリンクと同じボタン（`btn btn-outline-secondary btn-sm`）。
- 今の季節を見ているときも出す。範囲の端（2000年春・2100年冬）でも出す。
- 保存していない入力は、前後のリンクと同じく、確認なしで捨てる。
- 要件定義書は直さない。

## 決めること（上の決定で決まったものを除く）

- **ラベルの重なり**：テストが確かめる既存の文言〔「前の季節」「次の季節」、メニューの「予算」「予実比較」〕と、部分的に重ならないこと〔「今の季節」なら重ならない〕。
- **幅が狭い所**：iPad の縦で、「前の季節」「今の季節」「次の季節」と見出しが折り返しても崩れないこと〔実装のあと、画面で確かめる〕。テストが確かめるクラスは変えない。
- **変える文書**：設計書 2.3〔予算設定と予実比較の「表示」の行、保存していない入力の文〕、2.4〔「切り替え」の説明〕、4.4.2〔`fragments/season.html` の説明〕、2.7 など。**要件定義書は、直さない案**：要件 4.3・4.4 の文は変わらず、リンクは「季節を指定せずに開く」ことの別の入り口でしかない。→ 手順書に、直す前後の確認を書く。
- **テスト**：`SeasonSelectAssertions`〔共有の確認〕に、リンク `href="/budgets"`・`href="/comparison"` と文言を確かめる部分を足す。予算設定・予実比較それぞれで：今の季節を見ているときも出る、ほかの季節でも出る、範囲の端〔2000年春・2100年冬〕でも出る、リンクの先に `year`・`season` が付かない。既存のテスト〔メニューの `<a href="/comparison">予実比較</a>`、`href="/budgets">予算`、前後リンクの有無、`class="field-error"` など〕を壊さない。
- **ブラウザでの確認**：PC と iPad〔縦・横〕で、遠い季節からリンクを押して今の季節に戻る。今の季節で押しても問題ない。
