# 005：予実比較で、予算内の行（赤でも青でもない行）の右端に 💮 を出したい

## 概要

予実比較の表で、**実績があって予算内に収まっていて、青でもない行**の右端に 💮（白い花丸）を出したい、という要望。使っていて気分がよいようにするためで、**表示だけ**の変更。赤・青の決まりは変えない。**要件定義書にない機能**なので、要件に加える。要件定義書と設計書 5.9 から直す変更になる。

## 要望の内容

- 要望：予算オーバー（赤）ではなく、青（予算の1/3以下）でもない行で、**実績があって予算内**の行の右端に 💮 を出す。
- 理由：使っていて気分がよいように。
- **赤・青の決まりは今までどおり。** 青の行には 💮 を付けない。
- 今の判定（要件定義書 4.4、`BudgetColorJudge`）との関係：予算が設定されていて、実績が 0 円より大きく、予算以下（実績 ≦ 予算）で、実績の3倍が予算より大きい（青の ③ に当たらない）行が、💮 の対象になる。つまり、今は「色なし」で表示されている行のうちの一部。
  - 例（予算 30,000円）：実績 20,000円 → 💮。実績 10,000円（ちょうど1/3）→ 青で 💮 なし。実績 0円 → 青で 💮 なし。実績 35,000円 → 赤で 💮 なし。
  - 予算が未設定の行、予算 0円で実績 0円の行（色なしの②）は、💮 の対象外にする案（下の「決めること」で確かめる）。
- **Phase 8 の中で、4.4〜4.10 の確認のあと、画面の画像（Phase 9）の前に行う。** 確認（4.4〜4.10）は今の画面で済ませ、そのあとで足す。

## 決めること

- **合計行にも付けるか。** 合計の予算と合計の実績で、同じ判定（①〜④）をして、色なしで実績がある場合に付けるか。合計行は「科目の行」とは違う意味（全体のまとめ）なので、付けない案もある。
- **付けない行の確認**：予算が未設定の行、予算 0円で実績 0円の行は付けない、でよいか。実績が予算ちょうど（実績 ＝ 予算）の行は付けるか（色なしで、予算内）。
- **💮 の位置**：新しい列（右端）にするか、差額の列の右に同じセルとして添えるか。列を足すと、表の列の数が変わる（幅が狭い画面〔iPad の縦など〕での見え方と、表の見出しも決める）。
- **画面の読み上げ（スクリーンリーダー）向けの文字**：絵文字をそのまま読み上げると、「白い花」などと読まれて意味が通らない。`aria-label` や、画面に出さない文字（Bootstrap の `visually-hidden`）で「予算内」などと読ませるか、絵文字は飾りとして読み上げさせない（`aria-hidden="true"`）かを決める。
- **色の注記に 💮 の説明を足すこと**：今の注記「赤：予算超過／青：予算の1/3以下」に、「💮：予算内」などを足すか。
- **判定をどこに置くか**：色の判定は `BudgetColorJudge` の1か所だけ、画面は判定しない（設計書 P13、Q7-4）という決まりを守る。💮 も同じ場所で判定し、画面には判定済みの値を渡す。やり方の案：`BudgetColor` に値を足す／`ComparisonRow` に真偽値を足す。`row.color.name()` に頼る画面とテストへの影響を見て決める。
- **絵文字の表示**：💮 が、使う機器（Windows、iPad の Safari）で絵文字として表示されることを確かめる（Bootstrap の文字の指定には絵文字のフォントが含まれる）。文字が出ない・四角になる機器があるときの扱い。
- **変える文書**：要件定義書（4.4 に 💮 の決まりを足す。3章の機能一覧の予実比較の説明にも関わる）→ 設計書（5.9、2.3 の予実比較の表示、F4 や P13 に関わる記述）→ 手順書、の順。要件定義書は、直す前と後の文を先に見せてから直す。
- **テスト**：`BudgetColorJudgeTest`（境界値：実績 ＝ 予算、実績の3倍 ＝ 予算、予算 0円、未設定）、`ComparisonServiceTest`、`ComparisonControllerTest`（💮 の行に出る・赤・青・色なしで実績 0 の行・未設定の行に出ない、合計行）。**テストが確かめている HTML**（`<tr class="row-over">`、`<td class="num">` など）は壊さない。
- **CSV 出力（issue 004）との関係**：CSV に 💮 は出さない（表示だけの印）。
