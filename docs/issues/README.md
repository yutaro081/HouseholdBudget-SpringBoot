# docs/issues：不具合と要望の記録

作業中に見つかった不具合や、追加したい要望を書く場所です（[実行計画書](../plans/execution-plan.md) の進め方のルール7）。

## 書き方

- **1件につき1ファイル**で書く。
- ファイル名は「3桁の通し番号-内容.md」。例：`001-ログイン画面のエラー表示.md`
- 1件に書く項目：

| 項目 | 内容 |
|---|---|
| 概要 | 何についての不具合・要望か、1〜2行で |
| 再現手順または要望の内容 | 不具合：どう操作すると起きるか（期待した動きと、実際の動き）。要望：何がほしいか、なぜ必要か |
| 対応状況 | 未対応 / 対応中 / 対応済み / 対応しない。対応済みなら、直した内容や、関係する Phase・コミットも書く |

## 注意

- パスワードや接続情報など、秘密にすべきものは書かない。
- 要件定義書にない機能の要望は、要件に追加するかを決めてから対応する。9章「今後の予定」のものは、Phase 9 が終わるまで手を付けない。
