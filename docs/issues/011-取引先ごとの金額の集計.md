# 011：取引先ごとに、取引の金額を集計したい（期間は「年間」と「季節」）

## 概要

取引先ごとに、取引の金額を集計して見られるようにしたい、という要望。期間は「年間」と「季節」から選べるようにする。**実装は予定している**が、**今は記録だけ**で、コードも要件定義書も設計書も変えない。**要件定義書にない機能**なので、行うと決めたときに、要件定義書に加えるかを決める〔直す前と後の文を先に見せる〕。

## 要望の内容

- 要望：取引先ごとに、取引の金額を集計したい。期間は「年間」と「季節」から選べるようにする。
- 理由：科目ごとの予実比較はあるが、「どの取引先に、いくら使ったか」は、取引一覧を見て数えるしかないため。

## 今の状態（調べた結果。2026年11月4日。読むだけ）

- 取引先は、ユーザーごとに持つ〔科目・支払方法と同じ。要件定義書 3 章〕。取引は必ず取引先を 1 つ持つ〔`transactions.vendor_id` は `NOT NULL`〕。
- **予算は、科目ごとにしかない**。取引先ごとの予算はない。
- 今の集計は、科目ごとの実績だけ〔`TransactionRepository.sumByCategory`。`user_id` と「開始日以上、終了日の翌日未満」で絞る〕。季節の期間は `SeasonPeriod`〔冬は 12 月がある年。2000 年春〜2100 年冬〕が決めている。

## 決めること（例）

- **「年間」の区切り**：
  - 1 月〜12 月〔暦年〕。
  - 春〜冬の 3 月〜翌年 2 月〔今の季節の決まりに合う。冬は「12 月がある年」の考え方と同じ〕。
  - 4 月〜翌年 3 月〔年度〕。
  - どれを使うか。選べるようにするか。季節の範囲〔2000 年春〜2100 年冬〕との関係も考える〔暦年の 2000 年は、1・2 月が季節の範囲の外〕。
- **出すもの**：合計金額、件数、割合〔期間の合計に対する取引先ごとの割合〕。どれを出すか。割合の端数の扱い。
- **「比較」の意味**：
  - 期間の中で、取引先どうしを比べる〔多い順など〕。
  - 前の年・前の季節と比べる。
  - どちらか、または両方か。
- **予算と色との関係**：予算は科目ごとにしかないので、**取引先ごとは実績だけ**を出す。赤・青・💮 の色は、予算との比較で決まる〔`BudgetColorJudge`〕ので、**取引先の集計には付けない**案が自然。付けるなら、判定の元になる基準〔取引先ごとの予算がない〕を、新しく決めることになる。
- **取引のない取引先**：0 円で出すか、出さないか。並び順〔金額の多い順、名前順、登録順〕。同じ金額のときの順。
- **どの画面に置くか**：予実比較の画面の中、または新しい画面〔例：`/vendors/summary`〕。メニューの項目〔今は 7 つ〕が増えるか。年・季節・期間の種類を選ぶ欄を、予実比較と同じ部品〔`fragments/season.html`〕にできるか。
- **[issue 010](010-グラフを作成したい.md)（グラフ）との関係**：取引先ごとの集計を、グラフにする候補の 1 つ。先に表で作り、グラフは 010 で足す案と、一緒に作る案がある。**JavaScript を使う場合の決まりは、issue 008・009 と同じ**〔JavaScript を使う決まりは、本人の判断でゆるめてよい。ただし、決まりを変えるのは、JavaScript を使う機能を実際に作るときに、要件定義書・設計書から行う。そのとき、ブラウザで動きを確かめる方法も一緒に決める〕。表だけなら、JavaScript は要らない。
- **ログイン中のユーザーの取引だけを集計する**：これまでと同じ。集計の検索は、`user_id` で絞る〔取引先の ID で探すときも、ID と `user_id` の両方で絞る。CLAUDE.md、設計書 3.9〕。他のユーザーの取引を混ぜない。**データ分離のテストを、先に書く**〔2 人のユーザーで、同じ名前の取引先がある場合も〕。
- **自動テスト**：集計の正しさは、今の自動テストの形〔Repository、Service、Controller〕で確かめられる。期間の境目〔季節の境目、年の区切りの日付〕、取引のない取引先、金額の合計が `long` で足りること。
- **狭い画面での表示**：iPad の縦・横で、表が収まるか〔`table-responsive`〕。
- **変える文書**〔行うと決めたとき〕：要件定義書 → 設計書 → 手順書、の順。
