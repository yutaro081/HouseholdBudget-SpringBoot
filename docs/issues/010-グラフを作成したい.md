# 010：グラフを作成したい

## 概要

家計のデータを**グラフで見られる**ようにしたい、という要望。振り返り（[docs/retrospective.md](../retrospective.md)）の「次にやりたいこと」の 1 つ目。**今は記録だけ**で、コードも設計書も変えない。どんなグラフにするかは、これから決める。**要件定義書にない機能**なので、行うと決めたときに、要件定義書に加えるかを決める〔直す前と後の文を先に見せる〕。

## 要望の内容

- 要望：グラフを作成したい。
- 理由：表の数字を読むより、予算と実績の違いや、季節ごとの変わり方が、一目で分かるため。

## 決めること（例）

- **何をグラフにするか**：
  - 予算と実績の比較〔科目ごとに、予算と実績を並べる。今の予実比較の表に近い〕。
  - 季節ごとの実績の移り変わり〔春・夏・秋・冬、年をまたぐ変化〕。
  - そのほか〔科目ごとの割合、など〕。
  - 今の画面〔予実比較の表〕で足りない点が、何かを先に確かめる。
- **どの画面に置くか**：予実比較の画面の中、または新しい画面〔例：`/graphs`〕。メニューの項目〔今は 7 つ〕が増えるか。
- **グラフを描く方法**：
  - JavaScript のライブラリを使う〔ブラウザで描く。見た目の自由度が高く、動きも付けられる〕。ライブラリのライセンスの表示〔`THIRD-PARTY-NOTICES.md`〕と、アプリの中に 1 ファイルで置くこと〔CDN を使わない。会場でインターネットにつながらなくても動く。設計書 1.2〕を考える。
  - サーバー側で作る〔画像や SVG を HTML として返す。JavaScript は要らないが、描く部品を自作することになる〕。
  - CSS だけで作る簡単な棒グラフ〔Bootstrap の進行バーなど。種類は限られる〕。
  - **JavaScript の決まりとの関係は、[issue 008](008-ブラウザを自動で動かすテスト.md)・[issue 009](009-金額を入れやすくするボタン.md) と同じ**：JavaScript を使う決まりは、本人の判断でゆるめてよい。ただし、決まりを変えるのは、JavaScript を使う機能を実際に作るときに、要件定義書・設計書から行う。そのとき、ブラウザで動きを確かめる方法〔issue 008 の自動テストを先に入れるか、など〕も一緒に決める。「Bootstrap の JavaScript は入れない」は別の決まりで、変えない。
- **色の決まりとの関係**：予実比較の色〔赤＝予算を超えた、青＝予算の 1/3 以内、💮・薄い緑＝予算の 1/3 を超えて予算内、色なし＝予算 0 円・実績 0 円〕を、グラフにも使うか。同じ意味の色を使うと分かりやすいが、グラフの棒を赤・青で塗ると、「超えた・余裕がある」の判定をグラフでも行うことになる〔判定を 1 か所に置く決まり。`BudgetColorJudge`〕。色だけに頼らず、数字や文字も添える〔色の見分けにくい人にも伝わる〕。
- **自動テストで確かめられること・できないこと**：グラフに渡すデータの正しさ〔集計〕は、今の自動テストで確かめられる。描かれた見た目や動きは、MockMvc では確かめられない。人がブラウザで確かめるか、issue 008 で確かめる。
- **データの分離**：グラフに使うデータも、ID と `user_id` の両方で絞る〔CLAUDE.md、設計書 3.9〕。他の人のデータを集計に混ぜない。
- **狭い画面での表示**：iPad の縦・横で、グラフが収まるか。
- **変える文書**〔行うと決めたとき〕：要件定義書 → 設計書 → 手順書、の順。
