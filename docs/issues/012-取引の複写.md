# 012：過去の取引を複写して、新しい取引を登録したい

## 概要

過去の取引を複写して、新しい取引を登録できるようにしたい、という要望。同じような取引〔毎月の買い物、交通費など〕を、くり返し入れる手間を減らすため。**実装は予定している**が、**今は記録だけ**で、コードも要件定義書も設計書も変えない。**要件定義書にない機能**なので、行うと決めたときに、要件定義書に加えるかを決める〔直す前と後の文を先に見せる〕。

## 要望の内容

- 要望：過去の取引を複写して、新しい取引を登録したい。
- 理由：同じような取引をくり返し入れる手間を減らすため。
- **写した時点では、保存しない。** 取引の登録画面が、複写した値の入った状態で開き、「登録」を押して初めて保存する〔間違って増えないように。値は直してから登録できる〕。

## 今の状態（調べた結果。2026年11月4日。読むだけ）

- 取引の URL は、一覧 `GET /transactions`、登録画面 `GET /transactions/new`、登録 `POST /transactions/new`、詳細 `GET /transactions/{id}`、編集 `GET /transactions/{id}/edit`、変更 `POST /transactions/{id}/edit`、削除 `POST /transactions/{id}/delete`〔`TransactionController`〕。
- ID で探すときは、**ID と `user_id` の両方で絞る**〔`TransactionRepository.findByIdAndUserId`〕。他人の取引の ID は、404 になる。
- 登録画面は、**日付の初期値が今日**〔設計書 U7〕。

## 決めること（例）

- **日付を写すか、今日にするか**：複写元の日付をそのまま写すと、同じ日付の取引が増える。今日にすると、登録画面の今の決まり〔日付の初期値は今日。U7〕と合う。
- **何を写すか**：科目、取引先、支払方法、金額、摘要。全部写すか、一部だけ〔例：金額は空にする〕か。
- **ボタンの置き場所**：取引の詳細画面、取引の一覧、または両方。一覧に置くと、行ごとにボタンが増える。狭い画面〔iPad の縦〕で、行の中のボタンが押せるか。
- **URL の形**：登録画面に、複写元の ID を渡す〔例：`GET /transactions/new?copyFrom=（ID）`〕か、別の URL にするか。
- **他人の取引の ID を指定したら 404**：複写元は、**ID とログイン中のユーザーの両方で探す**〔これまでと同じ。`findById` は使わない。CLAUDE.md、設計書 3.9〕。存在しない ID も 404。複写元の ID が数字でないときの扱い〔今の `/{id}` と同じ決まりにそろえる〕。**データ分離のテストを、先に書く**〔2 人のユーザーで、他人の取引を複写できないこと〕。
- **保存しないこと**：複写の操作〔GET〕では、データベースに行を作らない。登録画面で「登録」を押して初めて保存する〔今の登録の処理を、そのまま使う〕。複写元の取引は変わらない。取引の登録は、入力チェックも今と同じ〔金額 1〜1000000 の整数、日付の範囲、取引先名・科目・支払方法がこのユーザーのものであること〕。
- **複写元の科目・取引先・支払方法が、変更や削除で今は選べないとき**：取引で使用中のものは削除できない〔要件定義書 3 章〕ので、複写元の選択肢は残る。名前を変えた場合は、新しい名前で選ばれる。
- **[issue 009](009-金額を入れやすくするボタン.md)（金額のボタン）との関係**：どちらも「入力を楽にする」という同じ目的。複写があれば、金額のボタンが要らなくなるかもしれない〔同じ金額をくり返す場合〕。逆に、金額が毎回変わる取引では、009 が役に立つ。**issue 009 は実装した（2026年11月4日〜）。複写を行うかは、009 を PC のブラウザで使ってみてから決める**（iPad での確認は行わない。2026年11月5日）。
- **JavaScript は要らない見込み**：複写は、リンク〔GET〕で登録画面を開く形にすれば、サーバー側の処理だけで作れる。JavaScript の決まり〔issue 008・009 と同じ。決まりを変えるのは、JavaScript を使う機能を実際に作るときに、要件定義書・設計書から行う〕は、この issue には関係しない見込み。
- **自動テスト**：Controller のテスト〔複写元の値が登録画面に入っていること、他人の取引と存在しない ID が 404 であること、複写しただけでは取引が増えないこと〕。画面の見た目は、人がブラウザで確かめる。
- **変える文書**〔行うと決めたとき〕：要件定義書 → 設計書〔2.2 の URL の表、2.3 の取引の登録画面〕→ 手順書、の順。
