# 023：科目から明細へ（科目別の取引一覧）（候補）

> **状態（2026年11月11日）**：☐ **候補**〔要望の一覧だけ。**要件定義書・設計書・コードは、まだ変えていない**。決めることは、この issue を進めるときに、一覧にして確認する〕。順番は、[issue 020](020-着地見込みの続き.md) のあと、**改めて決める**。

## 概要

予実比較の表で、**実績の数字を押すと、その季節・その科目の取引だけの一覧が出る**ようにする。数字（予算に対する実績）から、**中身の明細**へたどれるようにする要望。

## 要望の内容

### 1. 予実比較の実績の数字から、科目別の取引一覧へ

- 予実比較の表の**実績の数字をリンク**にする。押すと、**その季節・その科目の取引だけ**の一覧が出る。
- 理由：「食費の実績が多い」と分かっても、**何に使ったのか**は、今は取引一覧を自分で探すしかない。

### 2. 取引一覧に「絞り込み」を足す形にする

- 新しい画面は作らず、**今の取引一覧〔`/transactions`〕に、絞り込みの入力を足す**形にする。
- 例：`GET /transactions?category={id}&year=2026&season=autumn`
  - `category`：科目の ID。`year` と `season`：季節〔予実比較・予算設定と同じ決まり。設計書 2.4〕。
- **守りに関わる所**〔設計書 3.9。テストで確かめる〕：
  - **他人の科目の ID、存在しない ID は 404**。ID で探すときは、ID と `user_id` の両方で絞る〔`findById` は使わない〕。
  - 年・季節が範囲外・不正なときも 404〔予実比較と同じ〕。
  - 絞り込んだ取引にも、**他人の取引は入らない**。
- 絞り込みの値は、すべてパラメータで渡す〔文字列を連結した検索は使わない。設計書 7.4〕。

### 3. 一覧の上の見出しと、絞り込みを外すリンク

- 一覧の上に、見出し「**2026 年 秋・食費の取引（○件・合計 ○円）**」を出す。
- 見出しの近くに、**絞り込みを外すリンク**〔全部の取引の一覧へ。`/transactions`〕。
- 合計は、予実比較の実績と**同じ値**になること〔その季節・その科目の取引の合計。設計書 5.9〕。**件数と合計がずれない**ことを、テストで確かめる。

### 4. 検索の構想と、仕組みを共有する

- 構想：「**科目・取引先・摘要で、過去の取引を検索して、複写する**」〔[issue 012](012-取引の複写.md) の続き。構想の元は、リポジトリーの外の本人のメモ〕。構想の中身〔メモから、短く〕：
  - **登録画面に、検索の欄**〔科目・取引先・摘要〕を置く。当てはまる**過去の取引の一覧**から「**写す**」を押すと、issue 012 の `GET /transactions/new?copyFrom={id}` を開く。**写すだけで保存しない**は、012 のまま。
  - **GET のフォームで、JavaScript なしで作れる**見込み。**他人の取引は出さない**〔`user_id` で絞る〕。
  - **摘要の部分一致**は、LIKE の `%` と `_` を、**そのまま文字として扱う**〔記号として働かせない〕。
  - **使い分け**：**くり返しの取引は複写**〔検索して写す〕。
- 絞り込み〔科目・季節〕と、その検索〔科目・取引先・摘要〕は、**同じ「取引の絞り込み」の仕組み**を共有できる〔検索の条件を受け取り、`user_id` で絞って取り出す。画面の表示は同じ取引一覧〕。
- **別々に作ると、2 回作り直すことになるので、まとめて設計する**とよい。この issue を進めるときに、検索の構想も一緒に、一覧にして決める。

## 決めること（この issue を進めるとき）

- 絞り込みの条件の持ち方〔`category`、`year`、`season`、あとで足す `vendor`・`q`（摘要）など〕と、**検索との共有のしかた**〔1 つの条件の入れ物と、1 つの検索〕。
- 絞り込んだ一覧の**並び順・ページ**〔今の取引一覧と同じか。件数が多いとき〕。
- 絞り込みの入力を**画面に出すか**〔リンクで入るだけにするか、一覧の上に選ぶ欄を置くか〕。今回は、リンクで入る形を最小とする案。
- 見出しの言葉〔季節を指定しないとき、科目だけのとき〕。
- 予実比較の**どの数字にリンクを付けるか**〔科目の行の実績だけか、合計の行の実績も〔全科目〕か〕。
