## 概要

予実比較の表で、**実績の数字を押すと、その季節・その科目の取引だけの一覧が出る**ようにする。数字（予算に対する実績）から、**中身の明細**へたどれるようにする要望。

新しい画面は作らず、**今の取引一覧〔`/transactions`〕に、絞り込みを足す**。

## 要望の内容〔2026年11月11日・本人。11月19日に、決まったことに合わせて直した〕

### 1. 予実比較の実績の数字から、科目別の取引一覧へ

- 予実比較の表の、**科目の行の実績の数字をリンク**にする。押すと、**その季節・その科目の取引だけ**の一覧が出る。実績が 0 円の行と、合計の行は、リンクにしない〔段階 2〕。
- 理由：「食費の実績が多い」と分かっても、**何に使ったのか**は、今は取引一覧を自分で探すしかない。

### 2. 取引一覧に「絞り込み」を足す

- 例：`GET /transactions?category={id}&year=2026&season=autumn`
  - `category`：科目の ID。`year` と `season`：季節〔予実比較・予算設定と同じ決まり。設計書 2.4〕。
  - どれも省略してよい。受け付けるのは「なし」「`category` だけ」「`year` と `season`」「3 つとも」。指定がないときは、全期間・全科目〔今の一覧〕。
- **守りに関わる所**〔設計書 3.9。テストで確かめる〕：
  - **他人の科目の ID、存在しない ID、数字でない値は 404**。ID で探すときは、ID と `user_id` の両方で絞る〔`findById` は使わない〕。
  - `year` か `season` の片方だけ、範囲外・不正・空・2 回の値も 404〔予実比較と同じ〕。
  - 絞り込んだ取引にも、**他人の取引は入らない**。
- 絞り込みの値は、すべてパラメータで渡す〔文字列を連結した検索は使わない。設計書 7.4〕。

### 3. 一覧の上の見出しと、絞り込みを外すリンク

- 絞り込んだときは、件数の文の代わりに、見出し〔例「2026年 秋・食費の取引（3 件・合計 12,300円）」。冬は「2026年 冬（2026年12月〜2027年2月）・食費の取引（…）」〕を出す。文の形は手順書の決まったこと 7 と Q023-1〜3。
- 見出しの近くに、**絞り込みを外すリンク**〔`/transactions`〕。
- 合計は、予実比較の実績と**同じ値**になること〔設計書 5.9〕。季節の境目の日付で、**件数と合計がずれない**ことを、テストで確かめる。

### 4. 同じレシートの取引〔issue 032 のあとに足した〕

- 科目で絞ると、分けて登録したレシートの**一部の行だけ**が出る。編集・複写・削除は、今までどおりレシート全体が対象。
- 削除の確認の文の合計と行の数は、**絞り込む前のレシート全体**から作る。画面に出ていない行があるときは、「この一覧に出ていない ○ 行も消えます。」を足す。

### 5. 検索の構想との関係〔11月19日に直した〕

- 構想：「**科目・取引先・摘要で、過去の取引を検索して、複写する**」〔[issue 012](012-取引の複写.md) の続き。構想の元は、リポジトリーの外の本人のメモ〕。
- この issue では、**取引先〔`vendor`〕・摘要〔`q`〕の検索は作らない**。ただし、絞り込みの条件を「1 つの入れ物」にしておき、あとで項目を足すだけで、作り直さずに検索へ広げられる形にする〔手順書の決まったこと 6〕。
- 構想の中身〔登録画面に検索の欄、「写す」、摘要の部分一致で LIKE の `%` と `_` を文字として扱う、など〕は、検索を作るときに決める。
