# 004：家計簿のデータを CSV で出力して、Excel で開けるようにしたい

## 概要

取引などのデータを CSV ファイルとして出力し、Excel で開けるようにしたい、という要望。**要件定義書にない機能**なので、要件に加えるかを決めてから対応する（[docs/issues/README.md](README.md) の注意）。Phase 8（仕上げ）には入れない。

## 要望の内容

- 要望：家計簿のデータを CSV で出力して、Excel で開けるようにしたい。
- 理由：経理の経験から、Excel で集計や確認をしたい場面が想像できるため。アプリの画面にない並べ替えや集計も、Excel でできる。
- **今は Phase 8 に入れない。** Phase 8 のあと、別の Phase として行う。Phase 9（完成・引き渡し）の前か後かは、あとで決める。
- 新しい機能なので、要件定義書（3章の機能一覧、または9章）に加えるかどうかも、そのときに決める。

## 決めること（例）

- **何を出すか**：取引の一覧／予実比較の表／両方。科目・取引先・支払方法・予算も出すか。
- **どの画面に置くか**：取引一覧と予実比較に「CSV で出力」のボタンかリンクを置くか、専用の画面を作るか。URL の形（例：`GET /transactions/export`）。データを変えない操作なので GET でよいかも、ここで確かめる（設計書 2.1、7.6）。
- **出す範囲**：取引は全期間か、日付や季節で絞るか。予実比較は、表示している季節の表だけか。
- **Excel で文字化けしない文字コード**：Excel は、UTF-8 の CSV を、先頭に BOM（バイト順マーク）がないと文字化けして開くことがある。UTF-8（BOM 付き）にするか、Shift_JIS（日本語版 Excel の標準）にするか。改行コード（CRLF）と、項目を囲む `"` の扱いも決める。
- **CSV インジェクション（数式インジェクション）の対策**：摘要・科目名などの利用者が入力した値が `=`・`+`・`-`・`@`（先頭のタブ・改行も）で始まると、Excel で開いたときに**数式として実行される**危険がある。値の先頭に `'` を付ける、などの対策を決める。数字として出すべき金額の列（`-5,000` のような負の値）を、対策で壊さない方法も決める。
- **ログイン中のユーザーのデータだけを出すこと**：他のユーザーのデータを出さない（設計書 3.9、7.8）。Service は `userId` で絞る。2人のユーザーで確かめるテストを足す。ID を指定する形にはしない。
- **大きさの上限**：取引の件数が多いときの扱い（メモリに全部ためない、など）。
- **ファイル名**：例 `transactions-20261030.csv`。利用者が入力した値をファイル名に入れない（ヘッダーの注入を避ける）。
- **テスト**：文字コードと BOM、CSV インジェクションの対策（先頭が `=`・`+`・`-`・`@` の値）、データ分離、未ログインのときの動き、カンマ・改行・`"` を含む値。
