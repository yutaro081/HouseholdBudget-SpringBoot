# 006：ログイン中に、自分のユーザー名とパスワードを変更できるようにしたい

## 概要

ログインしているユーザーが、自分の**パスワード**と**ユーザー名**を変更できるようにしたい、という要望。**要件定義書にない機能**なので、要件に加えるかを決めてから対応する（[docs/issues/README.md](README.md) の注意）。Phase 8（仕上げ）には入れない。issue 004（CSV 出力）と同じく、Phase 8 のあとの候補にする。

## 要望の内容

- 要望：ログイン中に、自分のパスワードとユーザー名を変更できるようにしたい。
- 理由：今は、アカウントを登録したあと、ユーザー名もパスワードも変えられない（要件定義書 4.1 は、登録・ログイン・ログアウトだけ）。
- **今は Phase 8 に入れない。** Phase 8 のあとの候補にする。どの Phase で行うか（Phase 9 の前か後か）は、あとで決める。
- **「パスワードを忘れたときの再設定」は、別の機能**として、今回の範囲に入れない（要件定義書 8章「今回やらないこと」のまま。メールなどでの本人確認が要り、性質が違う）。
- 新しい機能なので、要件定義書（3章の機能一覧、4.1）に加えるかどうかも、そのときに決める。

## 今の仕組み（決めるときの前提）

- ユーザー名は半角英数字のみ・10文字以下、パスワードは半角の英数字と記号（空白は不可）で8〜30文字（要件5章。`RegisterForm`）。
- ユーザー名の重複は、データベースの一意制約（`uk_users_username`）と、照合順序 `utf8mb4_0900_as_ci` により、**大文字・小文字を区別せず**に防いでいる（`Test1` と `test1` は同じ）。
- ログイン中の情報（`LoginUser`）は、ユーザー ID・**ユーザー名**・**パスワードのハッシュ**を、セッションに持つ。画面上部のユーザー名の表示（`sec:authentication="name"`）は、これを読む。
- パスワードは BCrypt のハッシュで保存している（要件6章）。

## 決めること（例）

- **パスワード変更で、今のパスワードを確かめるか。** 確かめる案：今のパスワードの入力を求め、合っていなければ変更しない（ログインしたまま席を離れた間に、他の人に変えられるのを防ぐ）。間違いを繰り返し試せてしまう点（回数の制限がない）も確認する。
- **新しいパスワードの決まり。** 登録と同じ（半角の英数字と記号、空白不可、8〜30文字）にする案。確認用にもう一度入力させるか。今と同じパスワードへの変更を許すか。
- **ユーザー名の重複。** 大文字・小文字を区別しない（今の登録と同じ）。**自分自身の今の名前は重複とみなさない**（`Test1` を `test1` に変えるだけ、が通るように）。同時に同じ名前へ変更されたときは、一意制約の拒否を「重複」として返す（登録の `CategoryService` などと同じ考え方）。
- **ユーザー名を変えるとき、パスワードを確かめるか。** パスワード変更と同じく、今のパスワードを求めるか。
- **変更後に、画面のユーザー名やログイン情報をどう更新するか。** セッションの `LoginUser` に、古いユーザー名とハッシュが残る。案：(a) 変更後にセッションの情報を作り直す（ログインしたまま、画面上部の名前が新しくなる）。(b) 変更のあとにログアウトさせ、新しい情報でログインし直させる。
- **変更のあとにログインし直させるか。** 上の (b)。パスワードを変えたとき、**ほかの端末やブラウザで開いているセッション**（古いパスワードでログインしたもの）をどうするか。何もしなければ、ログアウトするまで使い続けられる。全部のセッションを終わらせるには、セッションの一覧を持つ仕組みが要る。
- **画面と URL。** メニューに「アカウント」を足すか、ユーザー名の表示から開くか。パスワード変更とユーザー名変更を1画面にするか、分けるか。URL の例：`GET /account`、`POST /account/password`、`POST /account/username`。変更は POST、CSRF のトークンあり（設計書 2.1、7.6）。
- **本人のデータだけを変えること。** 対象は、ログイン中のユーザー ID（セッション）で決め、画面から送られた ID は使わない（設計書 3.9、7.8）。他人のユーザー名・パスワードを変えられないことを、2人のユーザーで確かめるテストを足す。
- **成功・失敗のメッセージ。** 「パスワードを変更しました」「ユーザー名を変更しました」。失敗の文は、今のパスワードが違う場合と、入力の決まりに外れた場合を分ける。パスワードの値は、画面・ログ・メッセージのどこにも出さない（再表示でも残さない。設計書 7.9）。
- **変える文書**：要件定義書（3章の機能一覧、4.1。直す前と後の文を先に見せる）→ 設計書（2.2 の画面と URL、2.3 の項目、4.4.1 の Controller、5章の Service、7章のセキュリティ）→ 手順書、の順。
- **テスト**：パスワード変更（今のパスワードが違う／新しいパスワードの決まりに外れる／成功して新しいパスワードでログインできる・古いパスワードではできない／ハッシュが変わる）、ユーザー名変更（重複・大文字小文字・自分の名前・形式の誤り・成功後の表示）、未ログイン、CSRF、データ分離。
- **ほかの issue との関係**：issue 004（CSV 出力）や、パスワードの再設定（要件 8章）とは別。
